# Build & Product Philosophy
- Prefers to sequence work business-first: fully understand the business context and requirements before any technical/architecture discussion, which is deliberately deferred to a later step ("we'll go to the technical details later"). Confidence: 0.9
- Runs a startup-paced, deadline-driven build: move fast by "standing on the shoulders of giants" (managed services, AI-written code), and distrusts estimates that come from human timelines. Confidence: 0.9
- Strongly avoids over-engineering: keeps v1 scope tight to what the challenge/requirements actually need, defers non-required features ("Let's do just Public for now, this isn't coming out of the requirements, is it?"), and rejects anything that "overcomplicates" or risks becoming the build's bottleneck. Confidence: 0.95
- Prefers leveraging existing managed products/services (e.g., Clerk, Convex, Cloudflare email, Vercel, exe.dev, Flue) over building or hand-rolling equivalents; questions vendor choices if a big platform already offers the same capability. Confidence: 0.9
- Wants agent-friendly architecture: functions/APIs designed so agents can execute them, and prefers simple "expose tools + let the LLM figure out how to use them" implementations where an agentic approach genuinely makes things easier. Confidence: 0.85
- Values speed as a core product value for this startup product ("This is a startup focused product and it needs to be fast"). Confidence: 0.8
- Is cost-conscious about purchases/choices — explicitly asks for cheap options (e.g., a domain that is "available for cheap") and wants exact costs pulled from the tools themselves rather than ballpark estimates, comparing prices across domain options before deciding (e.g., picked the $9.99/yr .dev over the $80/yr .ai). Confidence: 0.85
