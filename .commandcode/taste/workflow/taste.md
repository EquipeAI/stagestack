# Working Process

- Prefers Q&A / interview-style working sessions focused on one specific area at a time, updating the docs incrementally as answers are confirmed — not large multi-topic passes ("This is a lot in a single pass..."). Confidence: 0.9
- Routinely dispatches sub-agents for research: quick tool/product research, verifying claims against challenge source material ("get a sub-agent to confirm with the source material"), integration research driven by usage examples, and cross-checking videos/transcripts against docs. Confidence: 0.95
- Wants the assistant to push back on scope, sequencing, and assumptions — not just agree — and to give honest takes on whether the work has gone too far, missed the mark, or is ready for the next phase. Confidence: 0.9
- Prefers confirming understanding before anything is written or saved ("Don't write anything yet, tell me your understanding"; "Don't save anything yet... give me your take"). Confidence: 0.9
- Prefers a specific docs structure: a docs/ folder with BUSINESS_CONTEXT.md and challenge-specific docs, plus a root PLAN.md that holds only the exact current tasks — explicitly not a massive "do everything" doc. Confidence: 0.9
- Commits work incrementally where things stand rather than waiting for perfect completion ("Let's commit things where they are"). Confidence: 0.7
- Expects the assistant to research/update itself on the latest state of the chosen stack (docs, versions, integrations) before building on it ("Go update yourself in most of these so you know what's the latest"). Confidence: 0.7
- Prefers the assistant to use the user's existing accounts and installed CLIs (e.g., a logged-in Vercel/Cloudflare CLI) to verify things like domain availability and exact pricing, rather than unauthenticated third-party lookups or asking for credentials; keeps the pricing questions flowing through that same CLI flow. Confidence: 0.8
- Prefers driving interactive CLI flows (purchase wizards, multi-prompt forms) through a tmux session — seeing the pane output via capture-pane and answering prompts with send-keys — instead of piping stdin blindly, since real TTY prompts don't consume piped input reliably ("Just use tmux so you can see and send keystrokes"). Confidence: 0.9
