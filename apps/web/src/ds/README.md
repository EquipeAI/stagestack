# `src/ds` — the StageStack design system (vendored)

This directory is a **vendored artifact**, not hand-written app code. It is
generated by and synced from the StageStack project in Claude Design
(DesignSync, project `3047afca-cf73-49aa-bf6e-5de2f789d6b5`), which is the
upstream source of truth for every component, token and asset in here.

```
index.ts            the ONLY import surface — `import { Button } from '~/ds'`
styles.css          single CSS entry point, imported by src/styles/app.css
tokens/*.css        design tokens; style with var(--…), never raw hex or px
components/**       37 components, each a .jsx + a .d.ts beside it
assets/             logo lockups, logomark, favicon, brand icons
```

## Why `.jsx` + `.d.ts` and not `.tsx`

Because that is how the vendor ships it. Claude Design emits plain JSX
components with a hand-authored `.d.ts` declaration file next to each one, and
that pair is what DesignSync writes into this directory on every sync. The
`.d.ts` is not a lossy afterthought — it is the component's documented API, the
same props the design project publishes, and it is what gives app code full
type-checking and editor completion at the `~/ds` import boundary. From
outside this directory a vendored `.jsx` + `.d.ts` pair and a `.tsx` file are
indistinguishable.

**Do not hand-convert these to `.tsx`.** It would buy nothing app code can
observe, and it would cost us the thing that makes this directory cheap: the
next sync would either overwrite the conversion or land 37 conflicts against
files the upstream project does not know we rewrote. Divergence from upstream
is the expensive failure here, not the file extension.

The same reasoning covers the rest of the directory: treat every file in
`src/ds/` as read-only from the app's point of view.

## Changing a component

Change it upstream in the Claude Design project and re-sync — never edit the
vendored file in place. If a component needs a prop it does not have, that is a
design-system decision made upstream; the `.d.ts` props are the entire API and
app code must not invent new ones.

Import only from `~/ds`, never from `./components/...` internals. That rule is
enforced by lint (`npm run lint:ds` in `apps/web`).
